# Nados AI — خطة التطوير الشاملة (من 6.3 إلى 9+/10)

> هدف الخطة: تحويل Nados AI من مشروع «يعمل محلياً» إلى **منتج AI إنتاجي متعدد المنصات** ينافس ChatGPT/DeepSeek بالعربية، دون كسر أي وظيفة قائمة، مع إبقاء الأسرار على الخادم فقط.

---

## 0) المبادئ غير القابلة للتفاوض
1. **لا أسرار في العملاء** (Web/Android) — كل المفاتيح على الخادم/Cloudflare Secrets.
2. **لا كسر للوظائف القائمة** — كل تغيير يجب أن يحافظ على الويب + Android.
3. **مصدر حقيقة واحد** — نفس الباك-إند ونفس قاعدة البيانات للويب والجوال.
4. **قابلية القياس والمراقبة** قبل أي توسّع.
5. **الصدق في المؤشرات** — لا ادّعاء قدرات غير مبنية (مثل تدريب 900B).

---

## 1) التشخيص الحالي (خط الأساس)
- المعمارية: React 19 + Vite (web) · Express (api) · Cloudflare Worker (edge) · Capacitor (Android).
- القوة: وظائف غنية (بحث عميق حقيقي، مساحات، مكتبة، إعدادات، تدريب، توجيه نماذج)، Android موقّع، 129/129 اختبار خادم.
- الخلل الأكبر:
  1. **النموذج المدرَّب Nados v1.1 لا يخدم فعلياً** (يجيب عبر المعلمين).
  2. **اعتماد على نفق Quick Tunnel + جهاز المستخدم** (هشاشة تشغيل).
  3. **لا مصادقة ولا عزل OS لتنفيذ Work**.
  4. **لا اختبارات E2E/جهاز**، ومؤشرات تدريب غير واقعية.

---

## 2) المعمارية المستهدفة (Target)

```
[Web App]┐
         ├──► Cloudflare (Edge: CDN, WAF, Rate limit, Auth edge, Secrets)
[Android]┘            │
                      ▼
             Nados API (حاويات دائمة: autoscale)
                      │
        ┌─────────────┼──────────────┬───────────────┐
        ▼             ▼              ▼               ▼
   AI Router     Nados v1.1     Tool Runtime     Object Store
 (تصنيف+توجيه)  (GPU serving)  (حاويات معزولة)  (ملفات/مشاريع)
        │             │              │               │
        └──────► Providers (احتياط) ─┴───► Supabase (DB/Auth/RLS)
```

**الركائز السبع:** باك-إند دائم · خدمة النموذج · مصادقة موحّدة · بيانات ومزامنة · أمان · مراقبة · CI/CD.

---

## 3) المراحل التنفيذية

### Phase 0 — تثبيت الأساس (P0 · 2–3 أسابيع)
**الهدف:** إزالة الهشاشة التشغيلية.
- نقل الخادم من «جهاز محلي + نفق» إلى **حاوية دائمة** (Fly.io / Render / VPS + Caddy) مع نطاق ثابت.
- `Cloudflare Worker` يوجّه `/api` إلى النطاق الثابت (لا Quick Tunnel).
- Health/Ready endpoints + Graceful shutdown + إعادة تشغيل تلقائي.
- CI/CD للنشر (GitHub Actions) + بيئات (staging/prod) + أسرار في Secret Manager.
- نسخ احتياطي دوري للإعدادات/البيانات.

**معيار القبول:** استقرار ≥ 99% خلال أسبوعين دون تشغيل جهاز المستخدم؛ لا انقطاع عند تغيّر جلسة.

### Phase 1 — تشغيل Nados v1.1 فعلياً كافتراضي (P0 · 2–4 أسابيع)
**الهدف:** أن يكون «Nados v1.1» هو النموذج المُجيب فعلاً.
- دمج LoRA في القاعدة + تصدير GGUF/AWQ.
- خدمة inference: **vLLM** أو **TGI** (GPU)، أو llama.cpp مُحسّن (CPU).
- Autoscaling + طابور + **fallback** إلى المعلمين عند السقوط.
- **Eval suite آلي** (دقة/هلوسة/التزام) لمقارنة v1.1 بالمعلمين قبل الترقية.

**معيار القبول:** v1.1 يخدم ≥95% بنجاح، ويتفوّق على المعلمين في الـeval، مع p95 زمن مقبول.

### Phase 2 — المصادقة والهوية الموحّدة (P0 · 2 أسابيع)
- **Supabase Auth**: Google / Apple / Email-OTP.
- JWT موحّد للويب وAndroid (Secure Storage على الجهاز).
- **RLS** لكل الجداول (محادثات/مشاريع/ملفات/إعدادات).
- ربط الجلسات الموجودة (migration) بحسابات.

**معيار القبول:** دخول موحّد من الويب والجوال، وعزل بيانات كامل بين المستخدمين.

### Phase 3 — البيانات والمزامنة (P1 · 2–3 أسابيع)
- Postgres/Supabase: `users, conversations, messages, projects, files, settings, runs`.
- **Object Storage** للملفات (S3/R2) + سياسات وصول موقّعة.
- مزامنة **offline-first** + حل تعارض + مسودات + cache.
- ترقيم صفحات + بحث فهرسي.

**معيار القبول:** نفس المحادثة تظهر وتتحدّث على الويب والجوال خلال ثوانٍ.

### Phase 4 — إكمال Work / Projects (P1 · 3–4 أسابيع)
- تنفيذ السلسلة: `Planner → Agent → Tools → Files → Execution → Test → Fix → Preview → ZIP`.
- **عزل OS حقيقي**: حاويات قصيرة العمر (Firecracker/gVisor/containers) + قيود موارد + شبكة مقيّدة.
- محرّر كود + طرفية + معاينة + اختبارات + auto-fix + تصدير ZIP.
- ربط المشاريع بالحساب في الباك-إند.

**معيار القبول:** مهام حقيقية تُنفَّذ بأمان، مع سجلات تدقيق، دون وصول لأسرار المضيف.

### Phase 5 — جودة الإجابة (مستمر)
- **Router ذكي**: تصنيف المهمة (رياضيات/كود/بحث/إبداع) → أفضل نموذج/مسار.
- **RAG** للملفات والمساحات + إعادة ترتيب المصادر + استشهادات دقيقة.
- **حماية من prompt injection** وتصفية المخرجات.
- تقييم مستمر (نموذج حاكم + اختبارات ثابتة).

**معيار القبول:** تحسّن مقيس في الدقة وتقليل الهلوسة على مجموعة تقييم ثابتة.

### Phase 6 — الأمان والامتثال (مستمر · تدقيق نهائي)
- تدقيق أمني مستقل (secrets, authz, CORS, SSRF, upload validation, path traversal).
- Rate limiting/WAF على Cloudflare · تدوير مفاتيح · إدارة أسرار.
- تخزين آمن للتوكنز + PII/تصفية السجلات.

**معيار القبول:** تقرير تدقيق بلا ثغرات حرجة/عالية.

### Phase 7 — Android للإنتاج (P1 · 2–3 أسابيع)
- **Push (FCM)** + `google-services.json` (خارج Git) + مُرسِل على الخادم.
- **App Links**: `assetlinks.json` ببصمة التوقيع.
- اختبار على أجهزة · Crash reporting · تحديثات داخل التطبيق.
- Google Play (Internal → Closed → Production).

**معيار القبول:** نشر ناجح على Play مع crash-free ≥ 99%.

### Phase 8 — Observability و SRE (مستمر)
- Logs/Metrics/Traces (OpenTelemetry) + لوحات + تنبيهات.
- SLOs (توفّر/زمن/خطأ) + On-call + Runbooks + نسخ احتياطي/استعادة.

### Phase 9 — UX والهوية (مستمر)
- إتاحة (a11y)، i18n، onboarding، سرعة الإدراك، مزامنة تصميم web/android.

### Phase 10 — النموذج الذاتي (طويل المدى)
- مسار حقيقي: بيانات → SFT → تقييم → DPO/RLHF → أمان، مع **مؤشرات واقعية** بدل المؤشر النموذجي الحالي.

## 6) مؤشرات النجاح (KPIs)
- التوفّر ≥ 99.5% · p95 زمن أول رمز < 2.5ث · معدل الخطأ < 1%.
- دقة الـeval ≥ 90% · هلوسة < 3% على الأسئلة الواقعية.
- crash-free sessions ≥ 99% · زمن بناء APK/AAB < 15 دقيقة.
- تكلفة/1000 رسالة ضمن الميزانية · زمن مزامنة < 3ث.

## 7) المخاطر وخطة التعامل
| الخطر | الأثر | التخفيف |
|---|---|---|
| GPU مكلف/غير متاح | تعطّل v1.1 | fallback للمعلمين + quantized + autoscale |
| تغيّر APIs المزودين/429 | تقلّب | تعشيش + حدود + مراقبة + مزودون متعددون |
| تسرّب أسرار | حرج | أسرار خارج العميل + تدوير + تدقيق |
| تنفيذ أوامر غير آمن | حرج | عزل OS + قيود موارد + شبكة مقيّدة |
| تكرار فقدان النفق | انقطاع | Phase 0 يزيله |
| ديون تقنية (ملف خادم ضخم) | صيانة | تقسيم `index.mjs` لوحدات + تغطية اختبار |

## 8) قرارات/موارد مطلوبة منك
- مضيف دائم (Fly/Render/VPS) + نطاق (اختياري) — للـPhase 0.
- حساب GPU أو ميزانية (RunPod/Modal/Cloud GPU) — للـPhase 1.
- مشروع Firebase + حساب Google Play — للـPhase 7.
- تأكيد نموذج العمل: «مجاني/تجريبي» أم «اشتراكات» (يحدّد الحدود والتحليلات).
